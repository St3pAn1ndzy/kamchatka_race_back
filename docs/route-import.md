# Импорт всей трассы KML/GPX

## Перед первым запуском

Применить миграцию перед запуском новой версии API

```bash
poetry run alembic upgrade head
```

Она добавляет необязательную высоту точки, прежние координаты не меняются

## Работа администратора

1. Создать сезон и нужные этапы, оставить этапы в запланированном состоянии
2. Открыть «Гонка и маршрут» и блок «Импорт всей трассы с КП»
3. Выбрать файл и нажать «Разобрать всю трассу» — на этом шаге база не меняется
4. Для каждой линии выбрать существующий этап нужного сезона, один этап нельзя использовать дважды
5. Проверить начальные и конечные координаты, при необходимости включить разворот и подтвердить направление
6. Назначить тип каждой именованной точки: КП, старт, финиш или лагерь
7. Нажать подтверждение замены всех выбранных этапов и КП
8. После сообщения об успехе обновить страницу и проверить карту

Запись заменяет линии и КП выбранных этапов, не создаёт новые этапы, участников или судейские отметки

Флаги судьи у импортированных КП изначально выключены — назначение судей проверяется отдельно организатором

Изменение километража раннего этапа требует включить в пакет также все последующие этапы сезона, чтобы не оставить неверный километраж КП от старта гонки

## Реальный файл «Берингия.Авача-2025»

- 6 папок этапов, 52 425 точек линии, 12 именованных точек
- На шестом этапе источник содержит линию первого этапа в прежнем направлении
- Если организатор подтверждает движение Пиначево → база Фатьянова, нужно явно включить разворот шестой линии
- Высоты исходной линии сохраняются без округления, высоты КП округляются до целого метра по существующей модели
- Изображение предпросмотра содержит до примерно 800 точек линии, сохранение использует все исходные координаты
- Публичный профиль высот отдельным API или графиком в эту работу не входит, исходные высоты сохраняются для его дальнейшей реализации

## Поддерживаемые структуры

KML: отдельная папка этапа с одной LineString и связанными Point; вложенные папки допустимы как контейнеры этапов

GPX: отдельный trk с одним trkseg либо rte на этап; глобальные wpt допустимы только при одном этапе, иначе привязка неоднозначна

Несколько сегментов GPX не склеиваются, сетевые ссылки KML, XML-сущности и DTD отклоняются

Лимиты: 8 МиБ, 32 этапа, 2–20 000 точек линии, 100 именованных точек на этап, 100 000 координат суммарно с учётом КП

При развёртывании за отдельным прокси лимит тела запроса должен учитывать 8 МиБ файла и накладные расходы multipart

## Защита данных

- Требуются сессия администратора и CSRF-токен страницы
- При подтверждении исходный файл разбирается заново, из браузера не принимаются произвольные массивы координат
- Запрещена замена начавшихся этапов, этапов с GPS и КП с любыми судейскими отметками, включая отменённые
- Весь пакет сохраняется одной транзакцией, ошибка не оставляет частично импортированные этапы
- Расчёт GPS и импорт используют согласованные блокировки до чтения геометрии
- Аудит содержит администратора, этап, контрольную сумму файла и количество точек и КП
- Кэши маршрутов, КП и справочника этапов сбрасываются после успешного commit

## Проверка

```bash
poetry run pytest -q
poetry run ruff check app/ tests/
poetry run ruff format --check app/ tests/
```

Тест с настоящим экспортом дополнительно запускается, если файл находится в локальной папке Downloads; остальные проверки используют встроенные синтетические примеры и не зависят от этого файла

## Задача Jira

**Название:** Импорт общей трассы KML/GPX с этапами и контрольными пунктами

**Эпик:** Админка

**Описание:** добавить предпросмотр общего файла, явное сопоставление существующим этапам, выбор направления и типов КП, сохранение исходных высот и расчёт километража

**Критерии:** реальный экспорт 2025 года читается полностью, направление не меняется автоматически, пакет сохраняется атомарно, данные начавшейся гонки защищены, изменения фиксируются в аудите, тесты проходят

CSV и демонстрационный симулятор не входят в эту ветку
